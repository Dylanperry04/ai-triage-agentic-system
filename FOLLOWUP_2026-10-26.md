## Clinical source finding and remaining requirement

Page 12 of the supplied 2018 IT guide, “Neuer unnormaler Puls”, proposes Orange
for pulse below 60 or above 100, or arrhythmia. It requires documented exceptions
for known rhythm disorder, athlete, child, or a recorded explanation. It does not
state that a pulse of 150 alone determines Red. The current model data lacks the
rhythm/new-versus-baseline information and exception assessment needed to
implement that workflow completely.

The [HSE 2023 national ED triage audit](https://assets.hse.ie/media/documents/HSE_National_Clinical_Audit_of_ED_Triage_Report_Final_1.pdf)
reports MTS edition 3 version 3.7 (2014) in the audited EDs. The
[HSE Emergency Medicine Model of Care 2025](https://about.hse.ie/api/v2/download-file/healthcare_professional_publications/Emergency_Medicine_Programme_Model_of_Care_2025.pdf/)
distinguishes adult MTS, children's ICTS and older-person modifications. Official
[MTS licensing guidance](https://alsg.zendesk.com/hc/en-gb/articles/4405111382930--MTS-Licencing-Manchester-Triage-System-MTS-content)
distinguishes framework and clinical content. A complete approved Irish adult
machine-readable discriminator catalogue was not supplied or found in the
public official sources searched. Research thresholds cannot be relabelled as
approved content.

Consequently, project thresholds remain unchanged: at exactly 150 bpm the
existing numeric safety floor is Orange; above 150 it is Red. At respiratory
rate 32.9 the floor is Orange. The final recommendation is the more urgent of
that floor and the model estimate. For example, a model estimate of 4 with RR
32.9 becomes 2; an estimate already at 2 stays 2. This distinction is supported
by boundary and orchestrator regression tests. These are project rules, not a
claim of official MTS approval. The separate heuristic pathway has not been
promoted to control the ML recommendation.

The request for a fully approved MTS discriminator decision pipeline remains
**partially fulfilled**: the evidence UI and existing override behavior work,
but the licensed clinical catalogue, additional structured observations and
clinical validation are still needed. See `MTS_REQUIREMENTS_REVIEW.md` and
`DISCRIMINATOR_PIPELINE.md` for the full requirements and model migration gaps.

## Confirmed problems and changes

- The panel always displayed general policy prose and secondary heuristic codes,
  even when neither changed the recommendation. Conditional rendering now
  reflects the actual recorded model-policy result, and the requested prose
  and secondary block are removed.
- The default source path required the full cohort/cache despite the requested
  small demonstration. A separate small repository now serves 100 in-memory
  cases; full training-source validation remains separate from serving-asset
  validation. Readiness, status, deployment preflight and smoke checks use the
  active cohort. The original full mode remains explicit.
- The post-deployment smoke verifier assumed 777,176/777,174 rows. It now
  verifies 100/100 by default and supports an explicit `--cohort full` check.
  Regression checks reject a full dataset when the expected release is 100.
- Review found mutable-return and reload/read race risks in the new loader;
  returned payloads are copied and reload/status/get operations are protected.
  Concurrent reload/read and mutation-isolation tests cover the final behavior.
- ZIP asset checks now use a complete Python manifest read, avoiding
  early-closing `unzip | grep -q` pipelines under shell `pipefail`. Missing
  assets and accidental full-cohort packaging fail validation.
- A credential-looking Azure OpenAI API key was present in the original tracked
  `.env.example`. The refreshed example has blank credential values. The
  earlier generated source ZIP was also sanitized. No key was tested or used.
  **If real, rotate it**: removal does not revoke an exposed credential or remove
  it from existing Git history or copies. Git history was not rewritten.

configuration properties, the demo manifest, the two offline selection scripts,
React evidence rendering/tests, readiness/status/preflight/smoke checks,

## Limits and delivery

The five Python warnings comprise two test-client dependency deprecations, one
NumPy compiled-extension size warning and two SciPy optimizer deprecations.
They remain visible. The 21 pre-existing skips concern retired full-MIMIC
active-source contracts, not new failures. Earlier dependency audits and Docker
limitations are documented in the initial audit. A live Azure deployment,
Azure billing reduction, real clinical performance, and live Azure LLM/SMS
integrations were not verified by this local follow-up. Existing Azure storage
and cache resources have not been deleted; the next deployment uses the small
cohort by default. The trained model still loads at startup/first inference.

The refreshed ZIP contains complete updated source and built frontend, with
100 runtime cases and the original model/evaluation artifacts. It omits the
optional full training CSV, runtime logs/caches, dependencies and Git history.
The patch omits `.env.example` to avoid reproducing the old key in removed-line
context; the sanitized template is included separately and in the source ZIP.
