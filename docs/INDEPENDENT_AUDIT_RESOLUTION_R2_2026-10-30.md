## Outcome and scope

The six reported reproducible defects were real. All six original probes failed against the starting code. The corrections below address their shared causes, rather than changing their assertions to manufacture success. An explicit **503 research-evidence integrity response** replaces the auditor's suggested 500 contract: both reject damaged evidence, while a valid empty study still returns an unevaluated report.

This remains a working synthetic-data research prototype. It contains eight source-transcribed MTS charts for age 16+, deterministic chart proposals with nurse confirmation, nurse-assessed findings, a pinned ML model, generic vital safeguards, frozen decision evidence and independent-review metric computation. It does not claim an autonomous trained MTS chart/discriminator extractor, clinical approval or completed hospital evaluation.

The original compressed CSV, trained model and selected 100 rows remain unchanged. The cohort still has 60 cases matching at least one generic vital safeguard. These are not 60 independently assessed official MTS findings. The original final-category distribution is 1/59/27/8/5 across Acuity 1–5, before new nursing observations. No resampling, fabricated observations, reference labels or retraining forms part of this release.

## Verification and research interpretation

The full backend suite passed **1,449 tests**, with **21 documented retired-MIMIC skips** and five warnings. The frontend passed **102 tests across 14 files** after a clean locked installation; its production build passed. Python `pip check` and compileall passed. npm audit and the runtime-requirements pip-audit scan reported no known vulnerabilities in the scanned resolutions. Five unchanged original external probes also pass after correction; the sixth expected a generic 500, while our dedicated corruption regressions verify the explicit 503 integrity contract permitted by the audit.

Warnings concern existing Starlette/httpx/AnyIO deprecations, a NumPy binary-size warning in the development test environment and SciPy optimiser deprecations. They did not fail the suite. A separately installed clean runtime is exercised during package verification; this does not replace environment maintenance or clinical validation.

During browser testing, a native JavaScript discard confirmation stalled the embedded preview's browser-control connection. The application now uses focus-managed in-page confirmation dialogs for changing patient, changing chart and reloading a draft. Cancel preserves the findings; explicit confirmation applies the action. Component tests cover cancel and confirmation, and the browser workflow is rechecked on the compiled build. The before-unload warning for closing a genuinely dirty page remains.

Detailed logs, XML, browser geometry and a package verification receipt accompany the local package. The current backend/frontend counts and dependency checks are recorded in `RELEASE_MANIFEST.json`; they report actual executions. The earlier `AUDIT_RESOLUTION_2026-10-30.md` remains a historical record of the first audit, including its older counts and viewport limitation.

The regenerated canonical replay invokes actual selection/safeguard functions on the same 116,576 previously accessed synthetic TEST rows and frozen split. Results remain:

- No new chatbot, dashboard rebuild, autonomous symptom extraction, all-54-chart expansion or wholesale architecture rewrite: the emails do not require them, and evidence does not justify the regression risk.
- No deletion of Streamlit/MIMIC compatibility, SMS, retraining exports, ITD tools or existing notification workflows solely to simplify the nursing view. Existing role restrictions and tests remain.

- No automatic model retraining, substituted patient rows, fabricated clinical labels, Azure resource changes or publication.
